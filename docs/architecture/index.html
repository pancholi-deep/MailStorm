Pattern references

These sources explain the patterns mapped to the code. They do not imply that every recommendation in each source has been implemented.

  1. R1 Asynchronous request/reply

    202 returns a durable ID; the browser polls status while workers run independently. Map: campaign_routes.py + emailApi.js.

  2. R2 Queue-based load leveling

    Durable DB jobs absorb requests; bounded worker claims, admission caps and pacing control processing. Map: Store.create / claim.

  3. R3 Idempotent API requests

    A caller key and content fingerprint protect campaign creation from duplicate requests. Scope ends before the external Gmail side effect. Map: Store.create.

  4. R4 Timeouts, backoff & jitter

    Deadlines, bounded retries, exponential delay and random jitter limit retry amplification. Only safe outcomes are retried. Map: worker.py + email_utils.py.

  5. R5 Fencing stale workers

    Increasing generations plus a live lease reject stale DB mutations. Gmail calls are outside the fence. Map: Store.claim / fenced / outcome.

  6. R6 Cryptographic storage

    Sensitive payloads use authenticated encryption; production keys are supplied separately. Key management and rotation remain operator duties. Map: Vault + config.py.
